Assessment Questions & Answers

I built this website using Visual Studio Code with plain HTML, CSS, and Bootstrap 5, then hosted it on Netlify. I chose these tools because they’re simple, quick to use, and don’t need a complex build setup. Bootstrap helped make the layout responsive and clean. I also stored my code in a public GitHub repository and connected it to Netlify for automatic updates.

One issue I ran into was a Git error saying “author identity unknown” when I tried to push my files. I fixed it by setting my Git username and email using the commands git config --global user.name and git config --global user.email. After that, I was able to push everything successfully and deploy the site on Netlify.

Netlify is very user-friendly. The automatic deployment from GitHub commits saves a lot of time and effort. I was impressed by the clarity of the dashboard and how fast builds complete even for first-time users.

For improvement, I think it would help beginners if Netlify displayed short “probable cause” hints for build failures. This would make troubleshooting easier without digging through full logs.

I think the Bootstrap documentation is one of the best examples of developer-friendly docs. It’s easy to follow and has a clean layout that shows both the code and what it looks like in the browser. The examples are simple enough for beginners but detailed enough to help you customize components.

What I like most is that every section looks consistent you can quickly find what you need without getting lost. As someone still building experience, I really appreciate how they include explanations, sample code, and accessibility notes all in one place. It helps me understand why something works, not just how to copy it.

1. Confusing record types (A, CNAME, ALIAS)
Many users aren’t sure which record type to use. For example, a CNAME can’t go at the root of a domain, and mixing them up can cause broken links or connection errors.

2. Slow DNS updates
DNS changes can take time to spread due to caching and TTL. People often think something’s wrong, but it’s usually just the update still propagating.

If I saw the error “Build script returned non-zero exit code: 2,” I’d first check the logs to find the specific line where the build failed, it’s often a missing dependency, wrong command, or syntax error. Then I’d confirm that the build command and publish directory in Netlify match the project setup. Since I can’t access the repo, I’d check for common issues like npm/yarn conflicts, missing environment variables, or outdated dependencies, and suggest clearing the Netlify cache before redeploying.

Customer-facing reply:
Hi there! I checked your build logs and saw the message “Build script returned non-zero exit code: 2.” This usually means something went wrong in your build setup like a missing dependency or incorrect command. Could you please share your build command and framework? In the meantime, try clearing the Netlify cache and redeploying, that often fixes temporary build issues.

I used a simple _redirects file to set up my redirect rules. This file tells Netlify how to handle certain URLs on my site.

301 redirect:

/netlify/*    https://www.google.com/search?q=:splat    301

This means any page under /netlify/ will redirect to Google with whatever word comes after it. For example, /netlify/test goes to a Google search for “test.”

Proxy redirect:

/api/*    https://httpbin.org/:splat    200

This lets my site fetch data from another service while keeping my domain in the URL.

I only used the _redirects file, and both rules worked after deploying.

I created a simple function in netlify/functions/hello.js:

export const handler = async () => {
  return {
    statusCode: 200,
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message: "Hello World" })
  };
};

The function worked on my first try and showed the message correctly at /.netlify/functions/hello. I didn’t run into any issues, but I double-checked that the file was in the right folder and that Netlify detected it in the deploy logs.
